# V1.8 複雜謄本情境支援工作計畫草稿

本文是 V1.8「工作計畫確認前」的文件整理稿，只用來釐清支援邊界、PDF 方向與待確認事項。此階段不進入實作，不修改公式、rounding、API endpoint、PDF template、DB schema、migration 或 production data。

## 1. V1.8 預計支援範圍

V1.8 討論後的目標支援範圍限於以下三類複雜謄本情境：

1. 單一筆土地，多位所有權人
2. 單一筆土地，多次取得
3. 多筆土地

這三類情境目前仍只是在工作計畫階段。正式支援前，GPTs 與 API 不應直接計算尚未實作完成的複雜情境。

## 2. V1.8 暫不支援範圍

V1.8 暫不支援以下兩類交叉複雜情境：

1. 多筆土地，多位所有權人
2. 多筆土地，多次取得

遇到上述情境時，應請使用者自行拆開計算或自行計算，不應由系統直接合併試算。

## 3. 為什麼 4、5 先不支援

「多筆土地，多位所有權人」與「多筆土地，多次取得」同時包含土地分組、持分歸屬、取得批次、課稅基礎與 PDF 呈現層級等多重複雜度。若在 V1.8 初期一次納入，容易造成以下風險：

1. 無法明確判斷每筆土地、每位所有權人與每次取得資料的對應關係。
2. GPTs 判讀謄本時可能把不同土地或不同權利人的資料交叉混用。
3. PDF 總表、明細表與合計結果的層級會過早複雜化。
4. 使用者若未先拆分資料，系統可能產出看似完整但實際歸屬不清的試算結果。

因此 V1.8 初期先把可控範圍收斂到單一複雜軸線：單一筆土地的多位所有權人、單一筆土地的多次取得，或多筆土地但每筆土地都必須是單純案例。

## 4. 多筆土地資料來源

多筆土地資料可能來自：

1. 使用者上傳多張土地謄本。
2. 同一份 PDF 內有多筆地號。
3. 一張謄本截圖裡同時出現多筆土地資料。
4. 使用者另外用文字補充每筆土地資料。

工作計畫需定義 GPTs 如何把每筆土地分組，並在資料不足或分組不清時要求使用者補充。

## 5. 多筆土地初期限制

多筆土地初期只允許每一筆土地都是「單純案例」。每筆土地必須同時符合：

1. 只能有一組權利範圍。
2. 只能有一組前次移轉年月。
3. 只能有一組前次移轉現值或原規定地價。
4. 只能有一組公告土地現值年月。
5. 只能有一組公告土地現值。

若多筆土地中任一筆又出現多位所有權人或多次取得，V1.8 先不計算，應請使用者自行拆開計算。

## 6. 多筆土地 PDF 決策

多筆土地 PDF 初期方向：

1. 預設產生 1 張合併 PDF。
2. PDF 內列出每筆土地明細與總計。
3. 不先做多張 PDF。
4. 未來可擴充成「一份 PDF 內多分頁」或「每筆土地各一張 PDF + 合計 PDF」。

PDF 區塊標題建議：

1. 一、多筆土地合併試算總表
2. 二、各筆土地計算明細
3. 三、單一筆土地多次取得明細
4. 四、合計結果

其中「三、單一筆土地多次取得明細」只適用於單一筆土地多次取得情境，不代表多筆土地多次取得已納入 V1.8 初期支援。

## 7. 土地面積欄位應加入 PDF 表格

多筆土地 PDF 表格需補上「土地面積」欄位，避免使用者只能從總額反推每筆土地的計算基礎。

第一層總表建議欄位：

1. 項次
2. 地號
3. 土地面積㎡
4. 權利範圍
5. 漲價總數額
6. 一般稅額
7. 自用住宅稅額

第二層明細表建議欄位：

1. 項次
2. 地號
3. 土地面積㎡
4. 前次移轉年月
5. 前次移轉現值
6. 公告現值年月
7. 公告土地現值
8. 調整後前次移轉現值

## 8. 後續才進入工作流程規劃

本文件目前只整理支援範圍、限制與 PDF 方向，尚不產出完整實作流程。待人工確認範圍後，後續工作計畫才應拆成：

1. GPTs 判讀與 gating 流程。
2. API payload 設計或既有 payload 延伸方向。
3. 計算流程與測試案例設計。
4. PDF 資料結構與版面設計。
5. 回歸測試與 production handoff 檢查。

以上項目仍須另行確認；本階段不修改任何實作。

## 9. 待確認事項

1. 單一筆土地多位所有權人：是否以「指定一位所有權人」為單次試算單位，或支援同一 PDF 內列多位所有權人的分列結果。
2. 單一筆土地多次取得：每次取得是否都需單獨列示前次移轉年月、前次移轉現值、權利範圍與對應稅額。
3. 多筆土地：使用者上傳多份謄本時，是否要求 GPTs 先逐筆列出資料摘要並請使用者確認後才試算。
4. 多筆土地合併 PDF：總表是否同時列一般稅額與自用住宅稅額，或依使用者選擇只列其中一種情境。
5. 多筆土地合計結果：是否需分別顯示一般稅額合計、自用住宅稅額合計與差額。
6. 多筆土地中若某一筆資料不足，是否整批暫停，或允許先計算資料完整的土地。
7. GPTs 生產規則何時從「先擋住」改成「依 V1.8 新流程計算」。
