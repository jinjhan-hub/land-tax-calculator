# V1.8 複雜謄本情境支援工作計畫草稿

本文是 V1.8「工作計畫確認前」的文件整理稿，只用來釐清支援邊界、PDF 方向、品牌識別要求與待確認事項。此階段不進入實作，不修改公式、rounding、API endpoint、PDF template、DB schema、migration 或 production data。

## 1. V1.8 預計支援範圍

V1.8 討論後的目標支援範圍限於以下三類複雜謄本情境：

1. 單一筆土地，多位所有權人
2. 單一筆土地，多次取得
3. 多筆土地

這三類情境目前仍只是在工作計畫階段。正式支援前，GPTs 與 API 不應直接計算尚未實作完成的複雜情境。

## 2. V1.8 暫不支援範圍

V1.8 暫不支援以下兩類交叉複雜情境：

1. 多筆土地，多位所有權人
2. 多筆土地，多次取得

遇到上述情境時，應請使用者自行拆開計算或自行計算，不應由系統直接合併試算。

## 3. 為什麼 4、5 先不支援

「多筆土地，多位所有權人」與「多筆土地，多次取得」同時包含土地分組、持分歸屬、取得批次、課稅基礎與 PDF 呈現層級等多重複雜度。若在 V1.8 初期一次納入，容易造成以下風險：

1. 無法明確判斷每筆土地、每位所有權人與每次取得資料的對應關係。
2. GPTs 判讀謄本時可能把不同土地或不同權利人的資料交叉混用。
3. PDF 總表、明細表與合計結果的層級會過早複雜化。
4. 使用者若未先拆分資料，系統可能產出看似完整但實際歸屬不清的試算結果。

因此 V1.8 初期先把可控範圍收斂到單一複雜軸線：單一筆土地的多位所有權人、單一筆土地的多次取得，或多筆土地但每筆土地都必須是單純案例。

## 4. 多筆土地資料來源

多筆土地資料可能來自：

1. 使用者上傳多張土地謄本。
2. 同一份 PDF 內有多筆地號。
3. 一張謄本截圖裡同時出現多筆土地資料。
4. 使用者另外用文字補充每筆土地資料。

工作計畫需定義 GPTs 如何把每筆土地分組，並在資料不足或分組不清時要求使用者補充。

## 5. 多筆土地初期限制

多筆土地初期只允許每一筆土地都是「單純案例」。每筆土地必須同時符合：

1. 只能有一組權利範圍。
2. 只能有一組前次移轉年月。
3. 只能有一組前次移轉現值或原規定地價。
4. 只能有一組公告土地現值年月。
5. 只能有一組公告土地現值。

若多筆土地中任一筆又出現多位所有權人或多次取得，V1.8 先不計算，應請使用者自行拆開計算。

## 6. 複雜情境 PDF 方向

V1.8 複雜情境 PDF 不要求固定公版。

原因：

1. 單一筆土地多位所有權人，重點在指定持分人與權利範圍。
2. 單一筆土地多次取得，重點在多個取得片段。
3. 多筆土地，重點在地號明細與合計。
4. 每次使用者上傳的謄本資料結構不一定相同，因此不適合強制一套固定內容版型。

PDF 方向為：固定品牌識別，不固定內容版型。

也就是：

1. 品牌視覺固定。
2. 頁首與頁尾規則固定。
3. 中間內容區塊依案例動態產生。
4. 不為複雜情境強制一套固定公版。

## 7. PDF 固定品牌識別要求

複雜情境 PDF 即使內容區塊依案例動態產生，仍需固定以下品牌樣式：

1. 使用太平洋紅白配色。
2. 頁首應有太平洋房屋 LOGO。
3. 頁首應顯示「土地增值稅試算報告」。
4. 頁首可顯示使用者名片或已確認營業員資料中的店名、公司名、營業員名稱。
5. 不得固定寫死「太平洋房屋員林站前店」。
6. 若名片或使用者輸入資料中可辨識店名，優先使用該店名。
7. 若可辨識公司名，應可顯示公司名。
8. 若可辨識營業員名稱，應可顯示營業員名稱。
9. 若沒有名片或營業員資料，頁首只顯示品牌 LOGO 與「土地增值稅試算報告」，不要自行補上店名、公司名或營業員名稱。
10. 表格表頭可使用太平洋紅底白字。
11. 內容背景以白色為主。
12. 合計列可使用淡紅或淡灰底。
13. 提醒區、免責聲明區可使用淺灰底。
14. 頁尾應保留製作單位與試算提醒。
15. 頁尾製作單位也應由名片或已確認營業員資料帶入，不得寫死固定店名。
16. 若沒有名片或已確認營業員資料，頁尾製作單位不得自行臆測或補值。

特別注意：

1. LOGO 只代表品牌視覺識別，不代表固定店名。
2. PDF 的店名、公司名、營業員名稱仍應由名片或使用者確認資料帶入。
3. 文件與後續實作不得把「太平洋房屋員林站前店」寫成固定頁首內容。

## 8. LOGO 檔案要求

目前 repo 已有 LOGO 檔案：

```text
public/branding/pacific/logo.png
```

V1.8 PDF 品牌 LOGO 應遵守：

1. 使用既有檔案：`public/branding/pacific/logo.png`。
2. 不新增第二份 LOGO。
3. 不替換既有 LOGO。
4. 不要求使用者每次上傳 LOGO。
5. 不由 GPTs 生成或重繪 LOGO。
6. PDF 產製時應由程式讀取 repo public 內既有 LOGO 檔案並嵌入。
7. Vercel 部署後可由公開路徑 `/branding/pacific/logo.png` 讀取。
8. LOGO 只作為品牌視覺識別，不代表固定店名。
9. 店名、公司名、營業員名稱應由使用者名片、使用者輸入或已確認營業員資料帶入。

## 9. 三種支援情境的 PDF 內容方向

以下不是固定公版，只是內容區塊原則。PDF 中間內容應依實際案例動態產生。

### 單一筆土地，多位所有權人

PDF 中間內容應可顯示：

1. 本次試算對象。
2. 該所有權人的權利範圍。
3. 土地總面積。
4. 本次計算面積。
5. 前次移轉年月。
6. 前次移轉現值或原規定地價。
7. 公告現值年月。
8. 公告土地現值。
9. 計算結果。

並明確標示：

1. 本次試算不是整筆土地。
2. 本次試算是指定持分人或指定權利範圍的試算。

### 單一筆土地，多次取得

PDF 中間內容應可顯示：

1. 取得片段明細。
2. 各片段分別計算。
3. 最後合計。

每個片段應列出：

1. 取得片段名稱或序號。
2. 權利範圍或取得比例。
3. 前次移轉年月。
4. 前次移轉現值或原規定地價。
5. 公告現值年月。
6. 公告土地現值。
7. 調整後前次移轉現值。
8. 漲價總數額。
9. 一般稅額。
10. 自用住宅 10% 情境稅額。

最後應顯示：

1. 一般稅額合計。
2. 自用住宅 10% 情境稅額合計。
3. 試算提醒。

### 多筆土地

PDF 中間內容應可顯示：

1. 多筆土地合併試算總表。
2. 各筆土地計算明細。
3. 合計結果。

多筆土地 PDF 初期方向：

1. 預設產生 1 張合併 PDF。
2. 不先做多張 PDF。
3. PDF 內列每筆土地明細與合計。
4. 多筆土地明細需包含土地面積欄位。

多筆土地表格可分成兩層。

第一層：總表

欄位：

1. 項次
2. 地號
3. 土地面積㎡
4. 權利範圍
5. 漲價總數額
6. 一般稅額
7. 自用住宅稅額

第二層：明細表

欄位：

1. 項次
2. 地號
3. 土地面積㎡
4. 前次移轉年月
5. 前次移轉現值
6. 公告現值年月
7. 公告土地現值
8. 調整後前次移轉現值

## 10. PDF 區塊標題建議

未來 PDF 可依案例顯示下列區塊標題：

1. 一、多筆土地合併試算總表
2. 二、各筆土地計算明細
3. 三、單一筆土地多次取得明細
4. 四、指定持分人試算說明
5. 五、合計結果
6. 六、試算提醒與免責聲明

這些是可選區塊標題，不代表每份 PDF 都必須全部顯示。PDF 應依實際案例顯示對應區塊。

其中「三、單一筆土地多次取得明細」只適用於單一筆土地多次取得情境，不代表多筆土地多次取得已納入 V1.8 初期支援。

## 11. 多筆土地 PDF 是否產生多張的決策

V1.8 初期不先做多張 PDF。

多筆土地初期採用：

1. 一份合併 PDF。
2. PDF 內列出每筆土地明細。
3. PDF 末端列出總計。

原因：

1. 下載連結較單純。
2. GPTs 回覆方式較穩定。
3. 測試成本較低。
4. 使用者可以在同一份文件內對照每筆土地。
5. 避免一開始就處理多個 download token、多檔案命名、多檔案下載問題。

未來可擴充成：

1. 一份 PDF 內多分頁。
2. 每筆土地各一張 PDF + 合計 PDF。

本文件目前只整理支援範圍、限制、PDF 方向與品牌要求，尚不產出完整實作流程。待人工確認範圍後，後續工作計畫才應拆成：

1. GPTs 判讀與 gating 流程。
2. API payload 設計或既有 payload 延伸方向。
3. 計算流程與測試案例設計。

5. 回歸測試與 production handoff 檢查。

以上項目仍須另行確認；本階段不修改任何實作。

## 13. 待確認事項

1. 單一筆土地多位所有權人：是否以「指定一位所有權人」為單次試算單位，或支援同一 PDF 內列多位所有權人的分列結果。
2. 單一筆土地多次取得：每次取得是否都需單獨列示前次移轉年月、前次移轉現值、權利範圍與對應稅額。
3. 多筆土地：使用者上傳多份謄本時，是否要求 GPTs 先逐筆列出資料摘要並請使用者確認後才試算。
4. 多筆土地合併 PDF：總表是否同時列一般稅額與自用住宅稅額，或依使用者選擇只列其中一種情境。
5. 多筆土地合計結果：是否需分別顯示一般稅額合計、自用住宅稅額合計與差額。
6. 多筆土地中若某一筆資料不足，是否整批暫停，或允許先計算資料完整的土地。
7. GPTs 生產規則何時從「先擋住」改成「依 V1.8 新流程計算」。
8. 太平洋紅的正式色碼是否要固定。
9. LOGO 在 PDF 中使用左上角或置中頁首。
10. 名片資料中若同時有店名、公司名、營業員名稱，頁首顯示優先順序為何。
11. 若名片資料不完整，頁尾製作單位是否留白或改顯示「未提供」。
12. 多筆土地 PDF 是否未來擴充為「一份 PDF 內多分頁」或「每筆土地各一張 PDF + 合計 PDF」。
13. 多筆土地超過幾筆時是否強制分頁。
14. 多筆土地表格欄位太多時是否改為橫向頁面或拆成兩層表格。
15. 複雜情境 PDF 是否需要保留現有單純案例 PDF 的所有欄位。
16. 複雜情境 PDF 是否需要另外標示「本報告為複雜謄本情境試算」。
